# Hermes Security Report

- Default state: `HERMES_ENABLED=false`, `HERMES_MODE=disabled`.
- Hermes v0.19.0 is installed externally at audited commit `32a9f2acbcc5c0da9e8e90ccd4c2c1189e5e5da6`; at rest no Hermes process, gateway, listener, schedule, learned skill, or external messaging integration is started.
- The adapter permits the audited `--help` and `doctor` diagnostics plus one official quiet CLI plan request when explicitly enabled. Planning forces safe mode, one turn, and the empty `context_engine` toolset. Every launch uses an argument list with `shell=False` and captured UTF-8 output.
- JARVIS accepts only pilot capability identifiers, never raw commands, executable paths, code, shell text, or input coordinates.
- The controller owns one adapter. `stop_task()`, shutdown, and emergency dispatch cancel its exact active process and descendants, clear adapter state, and cancel all Hermes task records in addition to existing automation/live-task stop paths.
- Piper remains the sole production speech service; no ElevenLabs dependency or configuration was introduced.

Regression evidence: 688 tests collected, 688 passed, 0 failed, 0 skipped. Blocking fake Hermes processes prove cancellation and timeout terminate and clear the owned process; a real GUI emergency-stop test interrupted Piper, released input, cleared pending commands, preserved JARVIS, and restored wake listening. The visible GUI confirmation timer owns its deadline and has bounded delivery grace, preventing worker races from leaving an orphaned approval dialog. A real schema-incomplete response was rejected despite containing only pilot capability IDs. Planned responses with no steps are now rejected rather than retained as executable approvals. The adapter and orchestrator reject any capability absent from the exact request and any permission/risk metadata that contradicts JARVIS's live registry record. Unregistered or unhealthy pilot names are never advertised. Research source reads resolve and reject all non-public destinations before retrieval, revalidate every redirect, reject embedded credentials and non-web ports, and Word save parameters are restricted to JARVIS's approved temp root. The trusted executor requires verified success before progress or output is recorded. Exact-session failure parsing surfaces safe provider status metadata while excluding private identifiers and secrets. Explicit health probing runs outside the GUI thread, reports the real external runtime without inventing a gateway, and was live-verified as responsive. Settings migration rejects the unsupported legacy `managed` value and obsolete model, forces autonomous flags off, fixes approval to `strict`, clamps concurrency to two, and passes only non-secret provider/model data to the live adapter. Shared Hermes command intents remain registered data-only requests; they cannot bypass action validation, and disabled planning returns without invoking the adapter or creating a task. `/background` creates only a reviewable plan; approval executes it interactively while unattended background execution remains disabled. A third active request is rejected before any provider call. Retained plans are keyed to a validated task, approval is single-use, denial executes no step, cancellation races cannot leave stale plan data, and emergency stop or shutdown clears every retained plan. Returned task records are detached snapshots, so callers cannot mutate manager-owned capability, permission, confirmation, or output lists. If cancellation wins during a bounded trusted step, its late return is discarded without progress, output metadata, retry, or terminal-state overwrite. Hermes audit writes are serialized JSONL metadata and the shared redactor now masks standalone bearer authorization values as well as keyed secrets.

The 2026-07-23 live Office interruption probe additionally proved that emergency stop closes the exact unsaved task document, leaves the task `CANCELLED`, releases automation input, restores wake listening, and produces no Piper synthesis or playback after the stop timestamp. A monotonic emergency generation now prevents late responses or remaining plan steps from restarting work or audio.

Remaining gate: no real response has passed the exact protocol schema, and five exact-schema retries returned HTTP 429. Hermes stays disabled and no candidate is promoted until a real protocol plan and the required safe pilots pass.
